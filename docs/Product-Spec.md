# CampusLink 产品需求

状态：0.3.0 公共插件设置已完成实现、针对性验证、独立复核及授权 Kwrt 设备升级/保存迁移/服务重启验收。原认证功能证据按未改动范围保留，公共配置证据见 [CL-UI-02](tasks/plugin-settings.md)及[0.3.0](testing/0.3.0.md)。

## 目标与用户

帮助 OpenWrt 用户保存校园网账号，为已有 WAN 配置认证提供商与学校参数，自动检查和恢复登录，并允许开源贡献者添加学校适配。通用框架不限制为两个账号或四路 WAN。

当前设备试用场景为 Cudy TR3000 256MB v1，运行 Kwrt 25.12-SNAPSHOT / firewall4；该场景另包含四路虚拟 WAN 与 mwan3 分流部署。

## 需求与验收

### REQ-001 四个虚拟 WAN（已完成）

- 在 eth0 上创建四个 netifd 原生 macvlan 设备，分别关联 wan1–wan4。
- 每个设备具有稳定且不同的单播 MAC；每个接口独立运行 DHCP。
- 每路 DHCP 默认网关进入自己的路由表，netifd 自动维护对应源 IP 的规则；不能只有四份地址而无法指定出口访问门户。
- 配置持久化到 UCI，属于 WAN 防火墙区域，保持 WAN 入站 REJECT 和 LAN 到 WAN 的 NAT。
- 保留 LAN、无线配置、现有 WAN 和管理凭据；提供可执行恢复脚本及配置备份。
- AC-001：`ip -d link` 显示四个 macvlan、父设备 eth0、MAC 互异。
- AC-002：四个接口可见于 LuCI，netifd 可分别报告 DHCP 状态；记录实际租约或上游拒绝/等待状态，不能仅用配置文件存在证明正常。
- AC-003：原 WAN 的默认路由及 DNS 保留，网页和 SSH 可访问，原单 WAN HTTPS 仍返回 200；防火墙检查通过。

### REQ-002 校园网登录管理软件包（0.3.0 已安装验证）

- 交付可安装的 OpenWrt 软件包，提供 LuCI 管理页面和后台服务。
- 单独管理账号列表，每条 WAN 选择账号、终端方式和线路开关；认证提供商、学校预设和公共覆盖参数在插件设置选择，字段及作用域由提供商声明。当前两个账号/四路接口作为试用场景，不写死到产品模型。
- 保留学校预设，允许手动修改认证地址与学校参数；选择提供商/学校后，常用表单只显示需要用户决定的信息，协议固定值与少见覆盖参数不逐项平铺。当前 Dr.COM HTTP 由认证服务器派生校园端点，特殊完整 URL 保留为高级覆盖；其他学校可贡献预设或新提供商模块。
- 展示每路 DHCP、认证、联网、重试状态；支持单路检查、登录、禁用、重试及自动恢复，退出/协议心跳仅在提供商支持时提供。用户在插件设置配置共用检查周期与重试间隔。
- 请求绑定对应出口设备和源 IP；区分校园门户、普通断网和已联网，限制重试频率及日志体积。
- 密码仅供 root 授权服务读取，界面遮蔽、日志不包含密码/令牌，不发送到云构建器。
- 不直接覆盖或执行旧脚本中的未知契约；核验当前校园网门户 API 后复用有效逻辑。
- AC-004：使用用户提供的账户与方式逐路认证，证明绑定正确；错误密码、缺租约、门户重定向及冷却状态可解释且不无限循环。
- AC-005：掉线后自动恢复并产生脱敏状态日志；服务启停可回读。
- AC-006：包可安装/升级/卸载，JSON 配置与既有网络保留策略明确，界面与 ubus 权限匹配。
- AC-008：账号可被多路引用，删除被引用账号会提示；读取账号不返回原密码；切换提供商可见其必填字段，学校预设与用户覆盖按明确优先级合并。
- AC-009：不同 WAN 的检查和重试互不覆盖，限流遵守冷却；未知 200/302、超时不能误报在线，登录返回接受后仍复查联网；接口/IP/配置变化使旧任务结果失效。
- AC-010：新增符合契约的学校预设无需改核心调度；新协议实现声明字段和能力并通过相同契约验证。核心对声明/结果执行语义校验，当前学校与 mock 已验证；新凭据类型须扩展账号校验和 UI，首版仅 username_password。
- AC-011：页面显示线路绑定账号及联网状态，不把绑定账号宣称为已核验的实际认证身份；首页、表头和正常联网行不反复展示身份未知说明。单路退出后自动登录暂停，验证目标出口未认证及其余出口未被误踢。不能证实的退出路径保留限制。0.2.0 展示规则已通过实际页面验收；本校退出仍未支持。
- AC-012（已验证，公共设置按 AC-013 调整）：功能按标签组织；新增登录配置可在同一弹窗选择或新增账号并绑定 WAN，无需先到另一块表单配置账号。特殊覆盖折叠、不支持的输入隐藏，隐藏字段无需另行补齐。取消不改变已保存数据；冲突保留草稿并提示；高级无效字段自动展开定位。
- AC-013（0.3.0 已验证）：插件设置统一选择提供商/学校/服务器、探测及共用检查/重试周期；WAN 表单只绑定账号、接口、终端方式和开关。同类旧配置迁移保留有效端点/周期/账号/密码/出口，异构旧配置保持原运行、由管理员选择后才统一；后台拒绝在每路覆盖公共参数。公共保存原子影响所有线路，失败/取消/冲突不覆盖，切换提供商/学校不沿用旧系统/学校地址。回退使用原包和升级前配置。验证范围见 [0.3.0](testing/0.3.0.md)，未再次真实踢出校园会话或重刷固件。

### REQ-003 四路 mwan3（已部署，已知验证边界见任务）

- 四路认证确认后配置 mwan3-nft 的独立跟踪、路由和均衡策略。
- 初始 wan1–wan4 等权均衡仅匹配 LAN IPv4 流量，读取现有 101–104 路由表；原物理 WAN 保留主表与 DNS，不作为第五个均衡成员。先关闭流量卸载验证完整转发路径，后续加速另行验证。
- 校园网认证请求保持指定出口。最终代理启用时再检查策略标记兼容；代理尚未启用，不把该后续检查计为本轮通过。
- 四路均衡、单路接口失效剔除与恢复已经实际验证，见 [MWAN-02](tasks/mwan3-setup.md)；校园认证失效但 ICMP 仍可达的情形尚未验证。
- AC-007：每路单独探测联网成功；多连接分流与单路故障切换实际验证，管理路径保留。

## 非目标与约束

- 本次界面优化仅更新 CampusLink 插件和相关文档，保留已完成的四路 WAN/mwan3 配置；代理接管、VNT 安装留待后续，不写 bootloader 或再次刷固件。先前 MWAN-02 的“本轮不改插件”限制仅适用于该网络部署任务，已由 D-20261008-07 的优化授权承接。
- 不承诺四路一定被校园网允许、不承诺单 TCP 下载获得四路带宽之和。
- 不修改用户的宿主机代理或长期路由配置。
- 通用框架与 mock 流程不依赖真实账号；本校适配和实际四路试用依赖账号、方式含义、门户行为及会话限制核验。AI 用于实现与验证，不作为路由器运行依赖。
