# CampusLink 产品需求

状态：0.3.0 公共插件设置已完成实现、针对性验证、独立复核及授权 Kwrt 设备升级/保存迁移/服务重启验收。原认证功能证据按未改动范围保留，公共配置证据见 [CL-UI-02](tasks/plugin-settings.md)及[0.3.0](testing/0.3.0.md)。

## 目标与用户

帮助 OpenWrt 用户保存校园网账号，为已有 WAN 选择登录系统与认证服务器，自动检查和恢复登录，并允许开源贡献者添加认证实现。通用认证框架不限制为两个账号或四路 WAN；可选 mwan3 联动当前仍有四路设备适配限制。

当前设备试用场景为 Cudy TR3000 256MB v1，运行 Kwrt 25.12-SNAPSHOT / firewall4；该场景另包含四路虚拟 WAN 与 mwan3 分流部署。

## 需求与验收

### REQ-001 四个虚拟 WAN（已完成）

- 在 eth0 上创建四个 netifd 原生 macvlan 设备，分别关联 wan1–wan4。
- 每个设备具有稳定且不同的单播 MAC；每个接口独立运行 DHCP。
- 每路 DHCP 默认网关进入自己的路由表，netifd 自动维护对应源 IP 的规则；不能只有四份地址而无法指定出口访问门户。
- 配置持久化到 UCI，属于 WAN 防火墙区域，保持 WAN 入站 REJECT 和 LAN 到 WAN 的 NAT。
- 保留 LAN、无线配置、现有 WAN 和管理凭据；提供可执行恢复脚本及配置备份。
- AC-001：`ip -d link` 显示四个 macvlan、父设备 eth0、MAC 互异。
- AC-002：四个接口可见于 LuCI，netifd 可分别报告 DHCP 状态；记录实际租约或上游拒绝/等待状态，不能仅用配置文件存在证明正常。
- AC-003：原 WAN 的默认路由及 DNS 保留，网页和 SSH 可访问，原单 WAN HTTPS 仍返回 200；防火墙检查通过。

### REQ-002 校园网登录管理软件包（核心 0.3.0 / LuCI 0.4.1 已部署）

- 单独管理账号列表，每条 WAN 选择账号、终端方式和线路开关；登录系统和公共覆盖参数在插件设置选择，字段及作用域由提供商声明。当前两个账号/四路接口作为试用场景，不写死到认证产品模型。

- 熔断状态与账号关联，提供脱敏原因和受影响线路。生效后不启动同账号新认证，同账号在途任务需取消或在认证前复核；已发送请求不可撤回，旧任务成功不能隐式解锁账号。普通检查、修改绑定/无关配置、时段结束、定期试登录、批量动作及服务重启不得静默解除；修正对应账号凭据或显式账号级恢复按统一范围处理，并继续遵守服务器冷却。
- 首版沿用现有提供商框架，补足可信分类与核心统一门禁；未知拒绝不凭宽泛关键词扩大影响，不声称可防止学校封号。恢复和等待说明属于必要功能交互，不增加可调熔断开关或阈值面板。联动资格仍依据当前绑定的实际联网/未认证证据，不因账号暂停自动关闭所有 WAN。
- AC-030（待验证）：四路同时到期可达 4 个在途 worker，任一路不重复；少于/多于四路仍遵守上限与公平调度，冷却、绑定变化、禁用/取消和旧任务结果拒绝保持正确。
- AC-031（待验证）：同账号多路被可信账号拒绝暂停，其他账号不受影响；普通失败/未知拒绝不误熔断；终端/设备限制的作用域可解释，分类以脱敏样本和针对性回归证明。
- AC-032（待验证）：熔断后的新请求、同账号在途竞争、旧成功结果、重启、无关保存、IP 变化及停网时段切换不能绕过统一门禁；修正账号/显式恢复正确作用于该账号并保留冷却，不主动退出原在线会话或改变网络配置。

### REQ-011 全部检查（需求已确认，待实现）

- 总览提供“全部检查”，目标为所有已启用的登录配置。沿用普通检查语义与自动登录开关；仅明确未认证且现有认证许可允许才登录，熔断/冷却/停网额度不因批量动作解除。不新增“全部登录”，不把全部检查标为只读诊断。
- 后台有界排队、单路去重，已有任务复用/等待而不重复启动；多于四路仍可完成本次有限批次。无接口等前提不足显示具体原因，停用线路跳过；配置/绑定变化使对应过期任务取消或重新按当前绑定校验，不把受理成功当成联网成功。
- 显示逐路受理/进行中/跳过/完成结果，重复点击不积累批次或形成无限重试；单路失败不阻止其余线路完成。入口与必要反馈复用当前控件，不伴随布局重做或新增参数。
- AC-033（待验证）：多路（含超过四路）批次受理、去重和最终结果完整；单路并发至多一、全局上限遵守，重复点击不放大请求，停用/无接口/忙碌/失败分别可解释。
- AC-034（待验证）：自动登录关闭、账号熔断、冷却和停网额度下的全部检查不偷发认证或解除保护；允许自动登录时先检查再认证；保存/绑定变化不写回旧结果，部分失败仍完成其余任务。

### REQ-012 mwan3 未知资格有条件过期（需求已确认，待实现）

- 只作用于已启用的受管映射。短时未知/在途检查保留资格；某路长期未知，且其他可参与分流的受管线路有新鲜、已完成、匹配当前绑定的联网成功证据时，暂时排除该异常线路，继续既有检查与恢复。宽限与证据新鲜度须结合实际检查/最大退避和主动降频策略确定，不机械固定 5–10 分钟，也不增加重复高频外网探测。
- 所有受管线路同时未知时，保留本轮决策前已实际应用的资格并提示无法确认，继续检查；不因此重新启用此前已退出、冷启动无证据或绑定变化的线路。此分支不提供硬性年龄上限；真实全线故障仍可能被保留，不能宣称绝无黑洞。
- 明确未认证、网口/租约/绑定失效等既有确定负面证据优先，全体未知保护不能覆盖它们。被排除线路须取得当前绑定下新的明确联网成功证据才能恢复，旧 online 快照不能恢复或续期。
- 分开记录最后一次联网成功和最近一次检查；失败及重复读取同一结果不刷新成功年龄。使用同一轮受管集合快照判断单路/全体未知，避免逐条执行造成连锁剔除。未启用/未映射线路不作为控制对象，诊断结果不绕过联动的正式证据校验。
- 主动停网等待、低频检查、账号保护和停止认证调度不等于断网；失联时只消费已有证据并遵守全体未知规则，不额外登录或解除账号门禁。原 WAN 兜底和策略能否由剩余成员承接须按设备验证，不作为通用保证。
- AC-035（待验证）：单路长期未知且其他受管线路有新鲜成功证据时排除该路，短时未知不抖动；全体同时未知保留决策前资格并提示，先前已退出成员不被重新加入，多路决策不依赖遍历顺序。
- AC-036（待验证）：成功年龄不被失败/重复快照刷新；旧结果、绑定/IP/配置/物理事件和时钟校正不能伪造新鲜证据；明确负面证据优先，恢复须有目标线路的新成功结果。
- AC-037（待验证）：停网主动降频、账号暂停、插件失联/重启及联动重启不被误判或隐式解锁；实际新连接由剩余健康成员承接，原认证出口和管理路径保持。未有可用剩余策略/兜底的环境披露边界，不凭四路样本宣称通用故障切换。
