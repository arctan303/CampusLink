## 结果与环境

原设备 Kwrt 25.12-SNAPSHOT、kernel 6.12.108、OPKG、ucode 2026.01.16~85922056-r2、mwan3-nft 3.6.12-r4。LuCI 0.4.0-1 → 0.4.1-1，核心 0.3.0-1 / addon 0.2.0-1 保留。总览增加公网 IPv4 列、手动查询/刷新和时间/过期/错误信息，原地址标为接口 IP。四路查询成功，观察到四个不同公网 IPv4；具体地址及截图仅在私有档案，不进入公开说明。

独立 `campuslink.diagnostics` rpcd exec plugin 隔离查询进程，复用核心已有 transport 的 ifhost!设备!IPv4 绑定、禁用代理、TLS 校验、禁止重定向及 4/8 秒超时。客户端只提交已有连接 ID；没有任意 URL、shell 命令、凭据或接口参数。get 只读缓存，query 全局 flock 互斥、单接口 60 秒冷却，/var/run 缓存 5 分钟后标为上次结果；设备/IP 或配置 generation 变化时拒绝迟到结果。查询不调用认证 action 或控制 mwan3。

固定查询端点为 [IPIP HTTPS JSON](https://myip.ipip.net/json)。候选 ipify 在指定 WAN 连接失败，IP.SB 返回 403，未作为自动回退。响应只提取 ret=ok 的 data.ip，不存储或展示服务返回的归属地/原始 HTML；它只能代表到该服务的直连路径，不能证明所有目标、代理或游戏加速器的出口。
