## 接入判断与建议顺序

1. **优先补齐现有深澜变体证据，再评估锐捷 RSA。** 北航/深圳大学工具自动提取 AC ID，部分状态解释接受 error 或 res；北航挑战解析主要检查 challenge 字段。当前 CampusLink 仍要求管理员填写 AC ID，状态/挑战要求特定 error，需用原始脱敏响应核对后才能放宽，不能仅从别人的解析器推断真实服务器一定缺字段。华科 RSA 示例包含密码/MAC 拼接、反转、零填充和多次编码，适合建立可复现向量；不能把“支持 RSA”当成一个无变体开关。
2. **大学掌 autewifi 值得单独定义适配任务。** 河南科技大学参考源码采用 /api/csrf-token、/api/account/status、/api/account/login，JSON 请求和 CSRF/Origin/Referer 头；作者注明 token 与 TCP 连接绑定。当前 transport 每个请求启动单独 curl，仅有 GET/表单 POST，没有 JSON/受控头和可跨步骤复用的连接。需要先验证会话传输设计；简单加一个字段或三个独立 curl 不足以实现参考流程。这里的连接绑定是上游观察，本轮未向学校服务器验证。[源码](https://github.com/heragehome/haust-auto-login/blob/4606385dd7c9e4e586a613f49b3b4d366047221d/CampusAuth.ps1#L25)
3. **广东天翼 CCTP 优先研究现成原生后端接入。** C 版源码已有初始化会话、ticket、登录与进程监管；Kotlin 版有 Algo-ID 和心跳状态机，另有 ESP32 移植。它们是同一实现谱系的交叉资料，不能算三种新协议。当前 provider 是短时 worker，heartbeat=false，不能直接承载持久会话；需研究独立客户端每 WAN 隔离、配置传递、状态读取和取消，再比较移植算法的成本。此项也未实施。[C 认证顺序](https://github.com/BadGhost520/ESurfingClient-CVersion/blob/cbc1f8ae2edf60abf66fe991af06698695356c0d/esurfingclient/app/src/clients/dialer/DialerAuth.c#L102)
4. **H3C iMC 与新版锐捷/CAS 留为会话型扩展。** H3C 示例有 pws?t=li 登录、Cookie 和 page/doHeartBeat.jsp；项目已因学校换系统停维。燕山大学实现有 portal-main/sessionId、页面 AES-ECB 密钥、Cookie、验证码及 CAS 票据，不能复用当前 InterFace.do 表单模块。需要新的会话/验证码交互能力，优先级低于免交互协议。[燕大认证源码](https://github.com/Youwenqwq/ysu-sdk/blob/ee07091873bad400a3de96b72cb4126400446318/ysu_sdk/eportal/client.py#L1)
5. **UDP/PPPoE/802.1X 与浏览器工具分开评估。** Dr.COM 客户端、MiniEAP、YaH3C 不走现有 HTTP 生命周期；浏览器工具需额外运行时。它们有参考价值，但接入将改变后台进程、依赖及网络权限边界，不能把 Python/Go/Playwright 整个搬到当前轻量包中就宣布完成。

## 对照时发现的边界

- **同校可能换系统或多区域并存。** 深圳大学资料区分教学区 Srun 与宿舍 eportal；南信大公开资料分别描述旧表单、新 raw JSON、Srun；河科大项目记录旧 GET/JSONP 与新 autewifi。它们不相互证明今天所有校区的协议，也不应按学校名自动选择算法。`eportal/portal/login` 路径本身不能识别厂商。
- **同源项目去重。** Sleepstars 明确 fork 自 Vidar；云南师大工具沿北理/BitSrunLoginGo 谱系；中大 MiniEAP 修改的是服务器心跳/状态机处理；天翼三个实现共享来源。清单用于覆盖变体，不等于 32 个独立系统。
- **README 与许可文件分别记。** HankLiu2020/iHDU-AutoLogin、SamizuHM/miwifi-whunet-login 的说明含 MIT 声明，但核对快照未找到根 LICENSE；MYHealer/esp32_esurfing 和仅 README 的 i-NUIST-login 也未核定许可证。清单以“待核对”保留，不作为直接移植授权。其余 SPDX 为 GitHub 识别或根 LICENSE 核对结果，实施前仍需核对引用文件及来源链。
- **只复用有依据的流程。** iHDU 源码成功日志包含用户名与密码变量；不采用这种日志行为。武汉大学模板和部分锐捷工具重放预填的加密表单，不等于已实现新密码的动态 RSA 认证。上游无限重试、宽泛成功匹配也不能替代当前暂停、冷却及联网复查契约。
- **已失效的资料作历史。** Pandaft/go-esurfing 明确说明 2024-03 接口变更后失效；ESurfingPy-CLI 说明部分学校关闭网页认证；H3C 示例也因校方换系统停止维护。没有把这些项目作为现役兼容证明。
