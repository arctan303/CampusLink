## 首审发现与关闭

### CL-UI-02-R01 · P2：Dr.COM 扩展示例把终端方式变成公共字段（已关闭）

首审证据：当时 `docs/contracts/examples/drcom-http.provider.json:10` 的 `terminal_mode` 没有 `scope: "connection"`；新版契约规定缺省 scope 为 global。前端 `config.js:81` 因此把首条线路的终端方式放进公共草稿，`:91` 从所有线路中移除该参数；后台也按相同缺省作用域处理。随包实际 Dr.COM metadata 已正确声明 scope，问题在当时交付的扩展示例。

首审独立重现：用当时示例及示例学校作为 model 的 data，建立终端为 `pc`、`mobile` 的两条 schema 1 假线路，调用 `settingsDraft` 后 `saveSettings`；结果两路 `params` 都为 `{}`，`model.params` 的有效终端均为 `pc`。这与契约声明的每路终端方式及“Dr.COM terminal_mode 为 connection”不符。该 Node 重现不发送请求、不修改文件。

后果：扩展作者采用当前示例时，电脑/手机字段出现在插件公共设置，显式统一保存后两种线路模式被合并，可能破坏认证会话；不影响当前正确的随包 metadata。

修复：提供商及学校示例同步当前随包 metadata，明确 `terminal_mode.scope=connection`，并对齐服务器、高级 URL、能力与 probe 默认值。关闭证据见下方第 1 次聚焦复核；没有修改后台实现。
