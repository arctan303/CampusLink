# PROXY-02：Nikki 本机控制面板

目标与依据：用户反馈 Nikki 面板打不开；D-20261009-12 / REQ-004 / AC-016。管理员通过已安装 Nikki 的“打开面板”入口使用本机面板，不将控制凭据发送到外部面板网站。

后续设备状态：用户在 D-20261009-13 / [NET-07](lan-management.md)关闭 Nikki，核心和 9090 面板随之停止；下面保留启用状态时面板修复的证据，按需再启用，不把主动停用导致的面板不可达当成新回归。

路线与规模：从缺陷诊断承接为短产品变更，因为 API 从回环改为 LAN 地址可达；用户请求已明确目标，按 product-spec-builder 记录并由 dev-builder 实施，不重复访谈。

根因：面板静态文件存在，本机 http://127.0.0.1:9090/ui/ 返回 200；LAN 地址相同路径连接拒绝。已安装 tools/nikki.js 的 openDashboard 固定使用浏览器所访问的路由器主机名与控制端口，无法访问回环监听。浏览器原生按钮打开的本机面板标签标题为“无法访问此站点”。此前配置仅验证了代理和 API 隔离，没有验证这个面板入口；属于该配置的遗漏。

范围：Nikki 的 API 监听地址和独立控制密钥；修正原生面板入口与当前 MetaCubeXD hash 路由的参数兼容。在本机已安装面板上验证入口、核心连接、代理组/连接/实时统计。回退备份与部署脚本同步。非目标：CampusLink 核心/账号、透明代理规则、mwan3 标记/成员策略、路由/防火墙/无线、VNT、固件、整机重启及宿主长期代理。

第二个已复现原因：当前面板可加载但仍默认连接电脑的 127.0.0.1。原生 tools/nikki.js 将 hostname/port/secret 参数放在 hash 前，当前面板使用 hash route.query 读取自动连接参数；同一组参数移入 /ui/#/setup 后，浏览器立即显示已连接路由器及实时统计。仅修改当前默认 MetaCubeXD 分支的链接，不改命名子面板分支或发送凭据到外部面板。官方依据：MetaCubeX/metacubexd 的 packages/ui/pages/setup.vue。

风险：R1，绑定仅本机 LAN 地址、管理员角色不变；用 64 位十六进制随机密钥替代原 6 字符控制密钥，未认证和旧密钥须拒绝，WAN 监听与开放均禁止。可能影响代理短暂重启及控制连接，按原故障入口和拒绝路径实测，保留只撤销两个配置字段的恢复入口。不更改路由器登录密码或新增管理员。

预期与验证：本机原生面板载入且显示核心已连接、代理组及连接/实时统计；API 401/正确密钥 200；仅 192.168.0.1:9090 监听。重启 Nikki 服务后单核心受 procd 管理；透明 TCP/UDP 短测、mwan3 四路在线及 CampusLink 指定出口保持；网络/无线/认证配置和本次启动 ID 不变。

依赖：原 PROXY-01 的 Nikki 2026.04.08-r15 / Mihomo 1.19.32-r34、已安装 /etc/nikki/run/ui、现有 LAN 和管理员 LuCI 会话。

状态：2026-10-09 已部署并完成针对性验证，R1 自查完成；未安排独立审查、未提交/推送。私有资料位于 `.local/proxy-mwan3/panel/`，密钥不写入公开文档或日志。

## 实施与验证结果

- API 仅监听 `192.168.0.1:9090`，采用 64 位十六进制随机密钥；无 WAN、IPv6 或通配监听。未认证和旧密钥访问 `/proxies` 均 401，正确密钥 200；通过 WAN 地址访问同一端口连接拒绝，原 WAN input REJECT 保留。
- `/ui/` 从 LAN 返回 200。默认面板链接由 `/ui/?${query}` 改为 `/ui/#/setup?${query}`，仅一行供应商兼容补丁。刷新 Nikki 页面后，原生“打开面板”按钮无需手工输入即可进入概览，显示连接 `http://192.168.0.1:9090`。代理组、实时连接列表及图表可读，截图时 19 个活动连接；这是实际当前流量，不能当成此次测试请求数。
- 配置校验通过；只重启一次 Nikki，核心 PID 13447 与 procd 一致，单实例。Nikki 原生 RPC 仍能读取核心版本，密钥变化没有破坏它的控制接口。
- 本次 WLAN 透明 TCP/UDP 回归 10/10，通过 TLS 证书和 UDP 响应校验；额外面板活动测试 4/4 HTTPS 成功。持有连接时面板列出测试设备到百度的直连流量，并持续更新局域网连接统计；远端关闭的连接不保证一直显示为活动。
- CampusLink、mwan3 四路均在线，跟踪仍关闭、每路 25%。vwan1–4 指定出口探测均 204，源地址分别 `.115/.114/.116/.132`。网络、防火墙、无线、CampusLink、mwan3、DHCP、Nikki init 和 mixin 哈希全部不变；本次前后启动 ID 均为 `c1ac27da-36ea-49a8-b191-370789c9e212`，无待提交 UCI。
- 配置应用时沿用原手动节点；随后面板可操作时观察到当前选择为住宅 UDP / 自动选择，未替用户覆盖。此前原生节点和四路 NAT 证据仍属 PROXY-01 的既有验证，不追认为此新选择的吞吐或长期稳定性验收。
