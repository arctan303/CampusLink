# CL-NET-01：按 WAN 查询公网出口 IPv4

目标与依据：2026-10-14 用户反馈电脑腾讯/网易游戏可能因多 WAN 的不同出口异常，希望首先看见各 WAN 的出口 IP，再考虑完善分流。承接 D-20261014-18；游戏异常的唯一根因尚未复现，两个电信账号不作为出口相同的证据。

范围/预期：总览区分已有接口 IPv4 与外部服务观察的公网 IPv4；每路手动查询/刷新，显示查询时间、过期/失败状态。通过独立管理员诊断 RPC、固定 HTTPS IPIP 端点及现有绑定传输执行，不依赖 mwan3 addon，不读取/发送校园密码，不变更认证核心状态或分流资格。

查询约束：最多一个查询同时执行，每接口至少间隔 60 秒；结果仅缓存在 /var/run，5 分钟后标为上次结果，不后台自动查询。接口设备/IP 变化即失效，完成时复核绑定及配置 generation，过期任务不回写；只接受公网 IPv4 格式的成功响应，不展示门户 HTML。外部服务只看到普通 HTTPS 请求的来源公网地址，不接收账号、局域网设备资料或凭据。查询反映直连到该服务的出口，不代表代理/游戏加速器或上游按目的地 NAT 的所有路径。

非目标：不实现 ASN/运营商识别、IPv6、游戏地址库、设备分流规则，不修改 mwan3 UCI、代理、网络、无线或校园配置；不保证游戏异常已修复，不推送或公开发布。

路线/规模/风险：产品变更、单一短任务、R1。错误绑定会误显示其他 WAN 的公网地址；使用现有 ifhost!设备!IPv4 传输、执行前后复核和过期结果拒绝。诊断失败仅影响诊断结果，HTTP 子进程由 rpcd 隔离、超时和互斥限流，不占认证 worker。沿用既有管理员 ACL，不开放任意 URL、命令或接口参数。

依赖：核心已有 public get 和绑定 transport、ucode/fs/ubus、curl、rpcd exec plugin；IPIP IPv4 HTTPS API。IPIP JSON 端点 https://myip.ipip.net/json 已在原 WAN1 绑定查询成功；ipify 无法连接、IP.SB 返回 403，因此不将它们作为自动回退。

验收/证据：原生规则/诊断流程验证成功、非法/私有 IPv4/门户/失败响应、缓存/冷却、绑定变化/配置竞争；真实 RPC 权限、并发互斥和 UI 查询/失败/旧轮询；四路设备查询与绑定、认证/网络配置保留。游戏设备固定 WAN 作为后续建议，尚未授权实施。

状态：2026-10-14 实施、打包和原设备更新完成，LuCI 0.4.1；原生 32 项、页面/参数回归、正式 RPC/互斥/缓存/匿名拒绝及四路真实查询通过。核心/addon/配置/成员哈希和进程保留；R1 自查，无独立审查、公开发布或推送。证据及回退见 [0.4.1](../testing/0.4.1.md)。游戏分流仍为建议，不是已交付功能。
