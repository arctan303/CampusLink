# MWAN-03：四路吞吐实测

目标：按用户要求测速，比较四个虚拟 WAN 单独与同时使用的实际下载吞吐，再验证 LAN 客户端经过现有 mwan3 均衡的总吞吐；用户期望约 400，暂按 Mbps 解释。

范围：检查链路速率与可用外网测速工具，使用明确绑定出口的有限时长测试。保留校园网插件、路由和代理设置；不刷机，不变更认证账号，不修改宿主机长期网络设置。

规模与风险：短任务，R1。测速短时间占用上网带宽和 CPU，测试进程设置时限；下载数据不落闪存。工具优先使用现有安装或可信上游的临时二进制。

依赖：当前四路认证在线、mwan3 等权均衡与出口绑定；核验 WAN 物理链路和客户端 WLAN 的速率，记录软件卸载状态与 CPU 影响。

预期行为与验收：给出四路单测、四路同期测试及 LAN 实际转发测试的速率/时间/节点/流量/出口证据；分别说明叠加比例和测试端瓶颈。不能将四次单测相加作为同期实测，也不能把路由器自身绑定四路的测试当成 LAN 分流验证。

状态：测速及结果分析完成。四路同期带宽叠加已证实；WLAN 客户端未证实稳定达到 400 Mbps。R1 自查完成，无独立审查或网络配置发布；没有安装常驻测速插件。

## 环境与工具（2026-10-08，Asia/Singapore）

- eth0 为 1000 Mbps / full duplex；Windows WLAN 接口 8、地址 192.168.0.139，协商速率 1.2 Gbps。软件和硬件流量卸载均保持 0，代理未启用。
- 临时使用上游 [speedtest-go v1.8.3](https://github.com/showwin/speedtest-go/releases/tag/v1.8.3)，Linux ARM64 发布档案 SHA256 为 `48f51504548d76d5dc2ce7f72e713bd3b4e35554028b7131467060688754c657`，与 GitHub 发布资产 digest 一致。二进制放在 `/tmp/campuslink-speedtest`，不写闪存。
- 外网节点为上海电信 `speedtest1.online.sh.cn:8080`（服务器 ID 3633），延迟约 32–34 ms；自定义 URL 仍指向同一节点。测试只下载，不测上传。每轮约 10–20 秒，不代表长期持续带宽。
- 单路及四路并行脚本：[measure-router-wans.sh](../../scripts/measure-router-wans.sh)。每进程绑定 vwan，下载 4 并发，45 秒进程组时限；每秒采样四路接口字节与 CPU。
- LAN 脚本：[measure-wlan-throughput.py](../../scripts/measure-wlan-throughput.py)。HTTP 套接字同时绑定 WLAN 源地址与 Windows IP_UNICAST_IF，使用路由器当时解析出的实际节点 IP；不改宿主机路由、代理或 DNS，下载体只计数、不保存。

## 结果

单位均为 Mbps，speedtest-go JSON 的 `dl_speed` 原单位为 bytes/s，乘 8 再除 1,000,000。

| 出口 | 单独测速 | 四路同时测速 |
| --- | ---: | ---: |
| wan1 | 100.79 | 98.62 |
| wan2 | 102.48 | 90.90 |
| wan3 | 99.61 | 99.24 |
| wan4 | 99.12 | 93.88 |
| 同期合计 | 不以四次单测之和冒充实测 | **382.65** |

同期工具报告合计为单路平均 100.50 的 **3.81 倍**，为用户预期 400 的 **95.66%**。这四个进程确实同时下载，原始采样进一步证明四路同期各约 100 Mbps。

接口计数按时间加权：四路均超过 20 Mbps 的完整同期区间为 9.51 秒，RX 总速率 **401.53 Mbps**，分别为 100.86 / 99.91 / 100.90 / 99.85。RX 含协议开销，不能与 HTTP 有效载荷速率混用。同期 CPU 平均 59.52%，两个核心平均 62.79% / 56.16%，最高单核样本 76.64%；本轮没有 CPU 持续饱和证据。

### LAN 实际转发

| 轮次 | 方式 | 稳态有效载荷平均 Mbps | 下载 MB | 超时连接 |
| --- | --- | ---: | ---: | ---: |
| 初测 | 16 并发，14 秒，大文件 | 332.18 | 578.10 | 1 |
| 复测 | 16 并发，20 秒，增大接收缓冲/超时 | 325.92 | 820.75 | 3 |
| 单服务器地址复测 | 16 并发，20 秒 | 260.90 | 673.16 | 8 |
| 与 speedtest-go 相同文件大小、复用连接 | 32 并发，20 秒 | **365.39** | 933.42 | 2 |

稳态计时扣除 2 或 3 秒起始阶段，按计时窗口内实际收到的 HTTP body 字节计算；并非瞬时峰值。最后一轮 484 次已获得响应的请求均为 HTTP 200，32 条初始连接中最终被动捕获到 30 条，mark 0x100/0x200/0x300/0x400 分别为 6/8/8/8 条；四路实际 RX 均持续增长。最后一轮接口 RX 同期均值 370.50 Mbps，CPU 平均 51.37%，最高单核样本 69.72%。

**结论：四路能够同时贡献带宽，LAN 的 mwan3 分流也在工作；本轮 WLAN 测试最佳一轮平均约 365 Mbps（45.67 MB/s），没有验证稳定 400 Mbps。** 大文件轮次和连接复用轮次都出现超时，不能直接归因为 Wi-Fi、校园网、服务器或 mwan3；前两轮只在某地址超时，换到另一地址仍超时，已排除仅凭该现象锁定单个服务器的说法。下一步若要定位 LAN 差距，应使用接入此路由器 LAN 的有线客户端和另一测速节点做对照；不通过盲目开启卸载追求数字。

这是多连接总吞吐验证；mwan3 按连接选出口，不提供单 TCP 连接四路带宽合并。没有验证上传、长时间吞吐、代理兼容或客户端 DNS。
