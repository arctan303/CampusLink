## 目标、范围与依赖

减少完成一条 WAN 登录配置时的步骤、输入与重复说明，保留账号多路复用、学校预设、特殊参数覆盖及现有认证能力。分析范围为已部署 0.1.0 LuCI 页面、提供商/学校声明、参数合并及状态文案来源。

本轮实施界面改版、打包及授权设备更新；替代此前仅分析的范围。不重做凭据系统、网络配置或认证协议。依赖已安装插件、当前授权设备、现有提供商与持久化契约；学校实际身份查询和退出能力未知不阻止界面简化。

## 已确认方向与建议方案

用户已明确：功能分页、删去点名的无用说明、减少配置步骤、提供商封装通用规则。此前确认的独立账号列表、学校预设及手动覆盖继续有效。

用户已授权按分析开始优化，具体交互选择记录于 [设计规范](../Design-Brief.md)：

- 原生 LuCI 标签页按“总览 / 登录配置 / 账号 / 日志”分区；四路 WAN 在各自列表中展示，不给少量线路强加数字翻页。
- 账号、线路使用紧凑列表，点击新增/编辑打开局部表单。登录配置内选择已有账号或直接新增，保存后账号仍进入独立列表，支持其他 WAN 引用。
- 普通 Dr.COM HTTP 配置为接口、认证提供商/学校、账号、认证服务器、终端方式、自动登录和检查周期；线路名称可自动生成后改名。
- 当前 Dr.COM HTTP 的默认端口/路径由适配器和学校预设封装；认证服务器统一驱动相关校园端点。非标准端口/路径、探测地址、重试与退避留在折叠高级设置；其他 Dr.COM 协议不因厂商相同而强行套用。
- 正常列表只显示联网状态、账号绑定和必要操作；错误时显示有操作价值的原因。每秒倒计时、协议限制和详细诊断放详情或日志，不常驻主表。
- 不支持退出时不显示退出地址；隐藏字段应有有效默认/派生值或不再必填，不能让表单保存依赖看不到的输入。

实际实现与验证：已有四 WAN/两账号配置可正常回读和保存；旧标准 URL 收拢、非标准覆盖保留、旧学校来源归一化、手动 HTTPS 端点、预设/服务器变更、取消/冲突/旧轮询防回退与原子账号保存均有针对性证据。真实浏览器完成分页、局部编辑、内联假账号新建/空密码编辑及清理、高级错误定位、键盘和小屏；原账号和四路配置比对一致、四路在线。具体范围见 [0.2.0 验证](../testing/0.2.0.md)，独立问题关闭见 [报告](../reviews/ui-simplification.md)。
