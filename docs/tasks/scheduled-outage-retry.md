# CL-SCHED-01：计划停网重试策略

来源：2026-10-14 用户准备开源插件，明确本校不停网，希望其他用户可配置停网时段和有限登录次数；随后确认每路每时段累计次数、普通/高级分层，以及默认严格限次、高级可选定期试登录。依据 D-20261014-19、[REQ-008 / AC-023–026](../Product-Spec.md)及[设计规范](../Design-Brief.md)。先前的直接到点休眠建议不作为本任务契约，采用有限尝试后等待的已确认方案。

目标与范围：提供默认关闭的可选公共调度规则，首版一个每日时段、支持跨午夜。普通区仅开关/时段/行为摘要；高级区含每路次数（默认 3）、用尽后策略（默认等待时段结束）和定期试登录间隔（默认 30 分钟，条件显示）。配置作用于公共设置，运行计数按线路和具体时段分别维护。

非目标：不实现其他九项优化、学校预设目录、多时段/周历规则、mwan3 TTL、协议响应分类扩展或任意脚本；不因本次确认推送 GitHub、公开发布、部署路由器或改动当前账号/网络/无线/代理。本校不默认启用。

预期行为：

- 只有进入自动认证阶段才消耗额度，超时亦计；纯探活和无可用接口不计。联网成功不重置本时段累计数。已有检查/退避/冷却继续控制尝试间隔。
- 严格策略用尽后保留不自动认证的低频检查，取得明确联网证据时更新状态。门户可达不解除额度；时段结束先检查，确认未认证且允许登录才认证。
- 定期策略用尽初始额度后允许按长间隔额外试登录，界面明确可超过初始次数。已有明确拒绝暂停、冷却、停用和关闭自动登录优先，不因规则结束或切换解除。
- 日志按策略状态变化记录；状态解释等待原因与下次允许时间。调度状态不直接代表 mwan3 故障，不新增独立重复高频探测。

依赖：现有 daemon/worker 的认证阶段、绑定校验、周期/退避及公共配置保存；LuCI 草稿/高级折叠结构；设备本地时区和可信时间。复用既有提供商结果，不依赖学校新增恢复 API。现有 worker 的 check 可能自动认证，因此耗尽额度后的检查必须明确禁止认证，不能只在界面隐藏登录按钮。

实施承接：补齐配置格式/旧配置默认关闭和回退策略；确定低频检查内部初值、时段归属、时钟校正及重启后的计数恢复；人工登录不应静默补满自动额度，保存无关设置或更换 IP 也不能绕过次数限制。当前没有运行实现，这些工程选择须落到针对性验证；不增加面向用户的内部调参开关。

路线/规模/风险：产品变更、单一短任务。当前仅记录需求与设计；后续实现预计 R1，影响可选时段内的自动恢复，默认关闭并可回退，须验证限次与恢复边界。若实现引入敏感数据披露、认证目标/账号绑定变化或可使全线长期无法恢复的具体路径，按影响重新评估，不能沿用预估代替验证。

验证与证据：

- 当前依据为本次对话确认和只读源码核对：daemon 的失败数包含不确定探测，不能直接充当认证次数；worker 只在确认未认证后进入 authenticating；现有 paused/cooldown 必须保留优先级。
- 实现时使用可控时钟、提供商和请求计数验证：关闭/非时段基线、每路预算、成功不清零、认证超时、检查不偷发登录、额度耗尽、定期额外尝试、跨午夜/时钟校正/重启/配置竞争，以及既有冷却和暂停。
- 页面验证普通/高级分层、条件显示、默认值、摘要、键盘/窄屏、保存冲突和草稿；兼容/回退及与已有联动状态验证后才更新现状。不用真实校园网反复认证或制造冻结来证明次数逻辑。
