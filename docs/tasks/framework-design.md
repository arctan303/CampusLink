# CL-FRAMEWORK-01：CampusLink 框架设计

来源：用户 2026-10-08 要求“先设计框架，后面让别人部署尝试”；此前确认学校预设可修改、账号独立管理、每 WAN 选择认证提供商和账号。
路线：产品设计，短任务。风险 R0：只新增/修订文档与声明示例，不改变路由器或认证运行行为。

## 目标与范围

给后续开发和试用者一份可承接的模块、数据、提供商接口、运行状态和验证边界设计。
范围：LuCI / RPC / 后台调度 / 提供商 / 学校预设、账号与 WAN 引用、敏感数据边界、重试状态、目录和构建目标约定。
非目标：本轮不实现软件包、不部署、不登录、不修改路由、mwan3、代理或已有脚本；不承诺四会话被校园网允许。
depends_on：已确认产品决定、现有脚本分析；设计不依赖真实账号。学校协议实现和设备试用另需脱敏样本、接口与目标 SDK。

## 预期行为与产物

- 每条已有 WAN 关联 provider、school、account，参数来自默认值与用户覆盖；字段由 provider 声明。
- 每路独立有界任务，确认未认证才登录，登录后复查，未知断网与凭据错误分别处理。
- 通用框架支持多个学校和 WAN，当前四路设备是试用场景。
- 产物：[架构](../Architecture.md)、[接口契约](../contracts/provider-v1.md)、两个 schema 与无秘密示例。

## 验证与证据

- 文档检查：`.creator/scripts/check_docs.py --root .`，确认相关本地链接、文件边界与结构。
- JSON/语义检查：解析 schema 与示例；核对必需字段、类型、声明字段唯一性、枚举/默认值、学校字段匹配和无秘密默认值。
- 人工对账：用户明确决定与设计选择分开；架构不把现有脚本模糊判断或设备四路约束变成通用规范。
- 原文件基线：五份已分析脚本 SHA256 与此前记录相同；不把其他会话的设备验证当作本任务验证。
