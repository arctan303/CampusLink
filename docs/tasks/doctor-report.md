# CL-DIAG-01：一键诊断与脱敏报告

来源与目标：2026-10-14 用户确认将“一键诊断＋复制脱敏报告”纳入面向开源用户的功能范围，当前以功能为主，手机卡片等布局优化后置。依据 D-20261014-20、[REQ-009 / AC-027–029](../Product-Spec.md)及[设计规范](../Design-Brief.md)，帮助具备基础 OpenWrt/LuCI 能力的管理员自查与分享可读证据。

范围/预期：管理员手动发起有界检查，按已有 WAN 的接口/IPv4、租约/路由、系统 DNS、实际认证端点、门户、绑定联网探测及可用的联动状态输出分层结果和操作建议，支持复制脱敏报告。缺失前提标为未执行，响应不足标不确定；可复制部分结果。复用现有诊断组件、ACL 和 LuCI 控件，不增加参数面板。

非目标：不自动修复、登录、退出、修改配置/路由/mwan3 资格，不扩展认证协议或读取凭据进行试登录；不开放任意 URL/命令，不后台持续探测；手机卡片、灯号仪表盘和其他未确认功能后置。本次需求确认不包含路由器部署、GitHub 推送或公开发布。

依赖：现有 CampusLink public status、netifd、绑定 HTTP 传输、rpcd 管理员权限和 LuCI；已有 [CL-NET-01](wan-public-ip.md) 已交付的诊断组件可复用，但仅公网 IP 查询证据适用于其原范围。mwan3 addon 可选，缺失时仅对应项不可用；不依赖未实现的停网规则、TTL 或其他优化。

关键约束：

- 使用当前配置的实际端点，检查绑定在执行前后复核。接口变化、状态变化和采样时间明确说明，不把整个过程宣称为同一时刻快照。
- 不调用可能自动认证的普通 action.check 完成只读诊断；认证请求计数必须为零。网络探测与认证 worker 隔离，限制总耗时、并发/请求次数和输出大小，沿用原管理员权限。
- 系统 DNS 与各 WAN 数据请求分别解释；认证端口可达不证明允许登录；单一探测失败不直接写成账号错误或线路必然断网。
- 分享报告通过允许字段构建，包含版本、时间、稳定线路代号、结论和建议；不复制原始配置/public get/完整日志。密码、令牌、Cookie、凭据 URL、原始页面省略；账号、IP、MAC 等可识别信息脱敏且保留必要关联。
- 诊断入口、结果和复制为必要交互；用文字表达失败/不确定/未执行，防重复提交，复制失败提供手动选取。具体 RPC 名称、总超时和内部探测初值由实现决定，不额外让用户调参。

路线/规模/风险：产品变更、单一短任务，当前仅需求/设计记录。后续实现预计 R1，沿用既有管理员权限与固定受控检查，失败影响限定于诊断。脱敏/绑定/资源隔离必须验证；若引入原始敏感数据返回、权限扩张或可占满认证资源的具体路径，重新评估风险，不能以“只读 RPC”自动按 R0。

验证与证据：使用可控接口/传输和请求计数验证成功、无租约/路由、DNS/端点/门户失败、不确定、超时、绑定变化和部分结果；验证不发认证、不改变保护配置和分流。覆盖权限、并发限流、缺失 addon、脱敏注入及复制失败。原生/设备验证按实际可用环境记录，不把结构检查或 CL-NET-01 的旧证据写成 Doctor 通过，不使用真实账号反复认证。

状态：需求已确认并记录；实施未开始，行为/脱敏验证未执行，未独立审查、打包、部署或发布。下一步从诊断数据模型、只读检查入口和脱敏报告构建开始实现；当前仍处于功能范围讨论。
